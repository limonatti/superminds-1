# Сохранность прогресса — второй этап

Цель: ответ ученика не должен пропадать при обрыве связи, закрытии страницы или повторной отправке запроса. Исправление предназначено для текущих индивидуальных учеников и групп; архитектура школ и подписки сюда не входит.

## Изменения

- `sm-auth.js` записывает каждое изменение в `localStorage` текущего аккаунта до обращения к сети. Каждая операция имеет отдельный ключ, поэтому вкладки не перезаписывают общую очередь.
- `apply_learning_events` применяет операцию и сохраняет её подтверждение в одной транзакции. Повторная отправка той же операции не начисляет баллы повторно.
- Ответы тренажёра и повторений изменяют текущую запись слова под блокировкой строки. Разные устройства сохраняют свои ответы, не заменяя весь объект прогресса.
- Баллы суммируются; поздняя отправка прошлой недели не сбрасывает текущую. Звёзды квеста сохраняют лучший результат, бейджи объединяются, кормление питомца учитывается один раз в день.
- Ответы учебников `__coursework` остаются под существующей отдельной защитой. Новая функция не позволяет изменять их через очередь словарного прогресса.
- Ошибка чтения больше не возвращает пустой прогресс. Кабинет, тренажёр и питомец показывают повторную загрузку. Тренажёр не показывает нулевую статистику до успешного чтения.
- Завершение квеста сохраняется без предварительного чтения прогресса и сетевого запроса `getUser`.
- Очереди принадлежат конкретным аккаунтам. Старый объект прогресса и ответы уже открытой страницы не переносятся в другой аккаунт после переключения.
- При отсутствии места в хранилище появляется предупреждение оставить страницу открытой; результат остаётся в памяти до отправки.
- Версия `sm-auth.js` обновлена в 138 корневых страницах и 8 встроенных учебниках, чтобы Service Worker не выдавал предыдущий скрипт.

## База и проверки

Миграция `durable_learning_progress` применена к проекту `kdzpmbuohfjbtjpqrdfx`. Файл создан CLI Supabase 3.0.0 и переименован в версию фактически применённой миграции `20261104201357`, полученную из истории базы.

Функция работает как `SECURITY INVOKER`, проверяет `auth.uid()`, использует RLS. Гость не имеет права выполнения. У таблицы подтверждений включён RLS; ученик может читать и добавлять только свои подтверждения, не может их удалять или менять.

Проверены:

- `tests/learning-progress.cjs`: настоящий клиентский обработчик вместе с PostgreSQL/PGlite — потеря сети, перезагрузка, потеря ответа сервера, новые ответы во время отправки, конкурирующие устройства, счётчики, недели, квесты, питомец, учебники, откат, смена аккаунта, RLS и нехватка места.
- `tests/learning-progress-ui.cjs`: реальная разметка кабинета, тренажёра и питомца в JSDOM — ошибка, кнопка повторения, отсутствие записи пустого прогресса.
- `tests/learning-progress-production.sql`: рабочая база, одна транзакция с `ROLLBACK`. Проверены подтверждение, повторная отправка, неизменность остальных данных и отказ гостю/чужому аккаунту. После отката в новой таблице 0 тестовых подтверждений; сохранены все 16 строк прогресса.
- `check.py`: 85 проверок; проверки SQL и клиентского сохранения учебников, доступа к комнатам, 56 проверок интерфейса комнаты.
- Supabase advisors: новых замечаний безопасности нет; замечаний производительности к новым объектам нет. Прежние замечания к другим объектам остаются отдельными задачами.

Браузерный инструмент не ответил при визуальной проверке. JSDOM-проверки интерфейса не считаются проверкой внешнего вида в настоящем браузере.

## Границы этого исправления

Для нового поведения нужно обновить открытые вкладки. Старые уже загруженные скрипты продолжают использовать прежний способ записи до обновления страницы.

Очередь переживает обычную перезагрузку и сохраняется в этом браузере; очистка данных сайта, закрытие приватного сеанса и удаление браузера удаляют локальные неподтверждённые записи. Для синхронизации нужно снова открыть платформу в том же аккаунте на этом устройстве. При первоначальной загрузке без связи прогресс не подменяется нулями: отображается повторная загрузка.

Исправление не меняет отдельные хранилища ответов учебников, итоговую отправку упражнения в `exercises.html`, расписание или восстановление чата. Эти задачи остаются следующими в очереди.

Для отката интерфейса достаточно откатить коммит выпуска. Таблицу подтверждений не удалять: она нужна, чтобы повторная отправка сохранённых в браузере операций не начислила результаты второй раз.
