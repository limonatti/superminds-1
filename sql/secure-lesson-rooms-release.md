# Закрытые доски и комнаты уроков

Первая часть исправлений по аудиту платформы от 04.11.2026.

## Поведение после обновления

- Для входа в доску или комнату нужен аккаунт. После входа пользователь возвращается по исходной ссылке.
- Комнату создаёт преподаватель. Владельца определяет сервер; параметр `s` больше не меняет роль.
- Преподаватель приглашает учеников кнопкой «Позвать ученика». Секрет приглашения находится во фрагменте ссылки, удаляется из адреса после входа и не возвращается участникам.
- Рисовать и сохранять могут владелец и приглашённые участники. Передача управления уроком разрешается преподавателем.
- Доски, изображения и каналы синхронизации закрыты для посторонних. Изображения показываются по временным ссылкам после проверки доступа.
- Старые доски сохраняются. Их первоначальный владелец раньше не записывался: открыть такую доску первым может только владелец платформы, после чего доска закрепляется за его аккаунтом. Ученикам нужно отправить новые приглашения.
- При сбое загрузки доски сохранение не запускается: пустой холст не перезаписывает сохранённый урок.

## Проверки

`python3 check.py` — обязательная проверка платформы, 80 проверок.

С установленными `jsdom` и `@electric-sql/pglite`:

```sh
node test-room.js
node tests/secure-rooms.cjs
node tests/secure-rooms-db.cjs
node tests/live-course.cjs
node tests/live-audio.cjs
```

Проверяются роли учителя/ученика, вход и отказ в доступе, подделка команд управления, приватные каналы, сохранение старых данных, права PostgreSQL и хранилища, опасный HTML в карточках, сообщения от посторонних окон, временные ссылки на старые изображения. Локальная SQL-проверка использует синтетические аккаунты. `tests/secure-rooms.sql` также можно выполнить в транзакции с `ROLLBACK` после миграции.

## Публикация без потери данных

Каноничная миграция — `secure-lesson-rooms.sql`. Для обновления действующего сайта она выполняется в два этапа:

1. Добавить столбцы, таблицу участников, функции и политики приватных каналов. На переходный период сохранить прежним клиентам доступ только к столбцам `room`, `data`, `updated_at`; запретить прямую запись владельца и чтение секретов приглашений.
2. Опубликовать `board.html`, `room.html`, `cabinet.html`, `sm-room-access.js` с обновлённой меткой кеша.
3. Выполнить блок миграции от `-- Direct clients` до `-- A separate teacher channel`: закрыть прежний публичный доступ к доскам и изображениям.
4. Проверить отсутствие доступа гостя, правила участников и открытие обновлённых страниц. Обновить ранее открытые вкладки досок и уроков.

Данные досок миграция не удаляет. Публичные каналы других разделов и настройки видеосервера Jitsi этим обновлением не изменяются. Старые уже открытые клиенты не переходят на приватные каналы автоматически — их необходимо перезагрузить.

## Следующий этап

Защита словарного прогресса при ошибке чтения и сохранение очереди повторения при потере сети. При проверке рабочей базы обнаружен уже действующий триггер `preserve_coursework_progress`: он объединяет ответы учебников, поэтому прежнее замечание аудита о перезаписи `__coursework` требует уточнения. Защита не распространяется на остальной словарный прогресс.
